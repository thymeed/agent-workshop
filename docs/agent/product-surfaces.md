# Live presence and product surfaces

Reference detail moved out of CLAUDE.md. Read it before editing the stage, cards, History, alerts or Live presence.

**Live presence** (hint + stage banner; `data-live-presence` on `#app`):

| State           | Meaning                                                                       |
| --------------- | ----------------------------------------------------------------------------- |
| `file-origin`   | Opened via `file://`. Use Electron or `http://127.0.0.1:port/` instead.       |
| `connecting`    | SSE connecting                                                                |
| `bridge-down`   | SSE failed. Show banner and manual Reconnect (no auto-reconnect loop).        |
| `no-projects`   | Bridge up but no projects found for the source in use (Claude Code or Cursor) |
| `quiet-healthy` | Connected, no recent events. Idle workshop, not an error.                     |
| `streaming`     | Active transcript traffic                                                     |

Dismissible first-Live coach sheet uses `localStorage` `ca.liveOnboard.v1` (never blocks Demo).

**Product surfaces (keep in mind when editing):**

- **Pixel-cast block agents.** Stage `#char-*`, Stations avatars, Insights empty states, and alerts share rect-body + square `.block-agent-eye` sprites via `AgentCards.faceMarkup` / `blockAgentSvgInner`. Role is **fill color only** (`data-avatar` tints in `cards.css`); no round faces, blush, chrome, mouths, or letter-circle initials. Stage figures include stub arms/legs; `.avatar-sm` uses compact blocks. `inferAvatarFromStatus` / `setStatus` drive block-agent state classes (`state-typing`, `state-done`, …); `setActive` only toggles `.card.active` + timing. Reviewing/Analyzing → `state-typing` (bob animation on `.block-agent-svg`).
- **Claude Code History.** In Live on Claude Code the History tab is available. Its sheet shows a session picker (`#claudeHistorySession`, `dashboard/claude-history.js`) filled from `GET /api/claude/sessions` (the 20 newest sessions of the selected project, only those from the last 14 days). Choosing one loads `GET /api/claude/session?id=<opaque>` (every event `replay: true`, subagent rows grouped by `source`) into the same replay transport (`insightsPanel.setReplayEvents`); choosing a session leaves the Live stage, Bill and log alone; the stage follows on scrub or Play, and `dashboard/claude-replay-guard.js` keeps the Live state that replay covers (a snapshot from `app.js`, plus the Live rows that arrive meanwhile) so that leaving History restores Bill, log, stage calls and cards and then applies those rows in order, quietly (today's Runs, tokens and fastest never change while the replay owns the stage: `AgentCards.setReplaying` freezes them and the guard's `release` dep unfreezes them when the replay ends); a source or mode switch, an SSE reset or a stream restart discards the snapshot instead, and `ReplayStage.mapHistoryEvent` passes these already live-shaped rows through. Replay only: the Insights forecast, suggestions and what-if never read Claude sessions (see the Insights bullet below for the live session they do show), and the replay never follows the live rows. A project pick stays on the current view (Cursor still opens History); a source, mode or project change drops the list and the replay. A truncated session says so. Known limits: the list shows an event count only once a session is opened (the list endpoint returns `events: null`), it includes the session Live is tailing right now, and a replay that queues more than 20000 Live rows rebuilds Live from the bridge's recent backlog instead of restoring.
- **History drawer from Stage and Insights.** On Claude Code the History drawer's own summary also lists the project's sessions when the view is Stage or Insights, and mounts the same replay transport (no page scroll), so a picked session plays and drives the stage there too; closing the drawer or switching view hands the stage back like leaving History. Cursor and Demo keep the old behavior (the drawer then points to the History tab).
- **History replay sheet.** `#historyReplayHost` mounts Insights replay transport (play/pause/scrub/speed) with shared `--insights-*` tokens; History view closes competing drawers, focuses the drawer (grid order + scroll to Play), remounts replay after async Insights load and on drawer reopen; scrub/play drives the stage via `replay-stage.js`. `GET /api/history` and Insights load use `filterHistoryToCurrentProject` in `live-bridge.js`, so only events whose `sessionId` exists under the **current** `TRANSCRIPTS` tree appear; empty project folder → no History events. Live **project picker** switches bridge scope, opens **History** (Cursor only; on Claude Code a pick stays on the current view), and reloads Insights onto the **latest non-empty transcript session** for that project (`latestSessionIdForTranscripts` / API `latestSessionId` + session picker default). In **Live on Cursor**, session load (`source === "session"`) paints the replay frame but leaves `replaySessionActive` false so **Live SSE keeps updating the workshop** until the user scrubs or presses Play (then replay owns the stage). SSE `reset` on reconnect does **not** remount History replay; only the project-picker path reloads Insights/replay.
- **Inbound route tokens.** `stageDirector.spawnRouteToken(role)` flies a mini block-agent glyph along the pulse path into the station on ask/delegate (`animateRoute`); cap concurrent tokens; respect reduced motion / narrow layouts.
- **TipLayer** (`tips.js`). One floating tip host for chrome, stage, cards, Insights, History, alerts; prefer `data-tip` / `data-tip-detail` over bare `title=` on primary controls.
- **Alert center** (`alerts.js`). Header bell; bridge SSE `event: alert` + `GET /api/alerts` (name/status/`agentId` only); loads after `cards.js` so rows can show role mini faces via `faceMarkup` + `roleFromAgentHint`; Electron desktop Notification stays on the same emit path.
- **Alert snooze** (`alerts.js` + `app.js` + `live-bridge.js`). **Indefinite** snooze, not a 15-minute timer: `ca.alerts.snoozeUntil` stores the sentinel `"indefinite"` (numeric legacy timestamps still honour `Date.now() <` until). The popover action toggles between **Snooze** and **Un-snooze** and stays open so un-snooze is reachable. While snoozed the unread badge is hidden, workshop audio is silenced (`sound.shouldMute()` = preference OR snoozed; the sound preference itself is untouched), and `alerts.js` posts `POST /api/snooze` so the bridge suppresses Electron **desktop toasts** while the SSE `alert` event and the in-memory ring keep flowing. Snooze is reconciled on load: `hydrate()` reads `GET /api/status` and re-pushes the renderer's `localStorage` state when the bridge disagrees, since the bridge resets snooze on `stopBridge()`, so snooze survives an app or bridge restart instead of silently un-gating toasts. Renderer wins because `localStorage` is the durable choice.
- **Insights / Stations.** Insights forecast + cost-ranked suggestions; Stations drawer hosts living cards; row/alert click → `jumpToAgent` (does not change Cursor routing).
- **Insights on a live Claude Code session.** `GET /api/history` returns no events there, so `app.js` hands every row it applies in Live on Claude Code (backfill and live alike, never a History replay's rows, the same rows the Bill gets) to `insightsPanel.addLiveRow`, and `resetUI` clears them (`clearLiveRows`). They stay in memory only and join the picker as the session "Live session" (id `live-session`; the bridge's own status lines, which carry no `type`, are not counted). Insights does not keep the rows: it keeps a row count, the first and last time, and input/output token totals per model (so memory stays small however long the session runs). The status line counts rows (one event per transcript row), the Forecast KPI and the model table sum those totals, and a row's usage is added to the total of `WorkshopBillMath.normalizeModel(usage.model, role)` and priced through `WorkshopBillMath.modelCost`, so the Forecast total is the Bill's total (any row type carrying usage counts, a delegation too; a row without usage names no model and only counts as an event). `No spend pace yet` shows only while nothing is spent (spend 0); with spend the pace is spend per day (a span under one day counts as one day). Money format differs below one cent (Insights `$0.0012`, Bill `$0.001`). History replay of an older session shows only its own events and is never mixed with the live rows. The Suggestions and What-if sheets show "Not available for live sessions yet." for the live session instead of a list (a live session has no per-agent pricing yet; an older session in the picker keeps both), and the session picker is rewritten only when the set of session ids changes. Today's Runs (`AgentCards.syncLiveSubs`) is the number of subagents that started, one per subagent transcript spawn row, not finishes; a spawn that arrives as Claude Code catch-up (a `replay` row) shows in subs but not in Runs (`AgentCards.absorbBackfillSub`), like its tokens. Tests: `test/insights-live-smoke.test.js`, and the totals (25,000 rows), the note and the picker in `test/insights-smoke.test.js`.
- **Ship celebration.** Portal burst + avatar `done` on merge/ship; respect `prefers-reduced-motion`.
- **Live presence.** `data-live-presence` on `#app` (`file-origin` … `streaming`); see table above.
- **Live SSE connect backlog.** `/api/stream` replays recent events with ephemeral `sseBacklog: true` so Stations daily "fastest" timing ignores connect-time replay even when the browser processes messages slower than the backlog quiet window (`liveSseBacklogReplay` in `app.js`). **Silent backfill.** `applyLiveEvent` has one motion gate: a row with `replay: true`, `sseBacklog: true`, or inside the backlog quiet window applies its state but raises no sound cue, route token, crate, spark, toast or ship celebration; only rows after the live edge animate. A row id the page already saw is not backfill (after a bridge restart the row ids restart while the project ids stay, so a new row can reuse an old id); it still skips timing and today's stats. A History replay is not backfill: Play steps animate one event at a time, scrub and play-start rebuilds are silent (`test/silent-backfill-smoke.test.js`).
